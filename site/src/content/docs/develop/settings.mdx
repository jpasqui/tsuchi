import { Tabs, TabItem } from '@astrojs/starlight/components';

Add settings to [your manifest](/develop/manifest/#settings), then read them through
[`settings`](/reference/settings/). Tsuchi loads the player's saved values before
your mod starts when the save is available. If a saved value arrives later, your
mod receives a change event. A delayed saved value can't overwrite a value your mod
has already changed. Settings can appear in the game's Settings tabs or on the mod's
page.

Open **Settings**, select **Mods**, and open the mod's details to edit its
declared settings. Players type text, integers, and numbers with the system's
keyboard, and choose a [binding](#bindings)'s button by pressing it.

## Declaration

For example, add a toggle for log messages:

```json title="mod.json"
{
  "id": "olimar.clock",
  "name": "Clock",
  "version": "1.0.0",
  "settings": {
    "report": {
      "type": "toggle",
      "default": true,
      "name": "Log messages",
      "description": "Write a message when the setting changes.",
      "public": true
    }
  }
}
```

Use `name` and `description` for the setting's display text. The manifest guide
lists every [setting key](/develop/manifest/#settings) and its allowed types.

## Changes

Read the initial value when your mod starts, then read it again when it changes:

<Tabs syncKey="language">
<TabItem label="Lua">

```lua title="main.lua"
local own_id = mod.id()
local function report()
    local enabled, why = settings.toggle("report")
    if enabled == nil then
        print("Can't read report: " .. why)
    elseif enabled then
        print("Log messages are enabled")
    end
end

report()
settings.on_changed(function(event)
    if event.mod == own_id and event.key == "report" then report() end
end)
```

```javascript title="main.js"
const own_id = mod.id();
function report() {
    try {
        if (settings.toggle("report")) print("Log messages are enabled");
    } catch (error) {
        print("Can't read report: " + error.name);

report();
```

<TabItem label="C">

```c title="main.c"
#include "tsuchi/tsuchi.h"

static const TSUCHI_Host *host;
static TSUCHI_Mod *self;
static TSUCHI_Subscription changes;
static char own_id[TSUCHI_ID_SIZE];

static bool same(const char *a, const char *b) {
    while (*a && *a == *b) { ++a; ++b; }
    return *a == *b;
}

static void report(void) {
    bool enabled = false;
    TSUCHI_Result result = host->settings->toggle(self, "report", &enabled);
    if (result != TSUCHI_OK) host->mod->log(self, "Can't read report");
    else if (enabled) host->mod->log(self, "Log messages are enabled");
}

static void on_changed(void *user, const TSUCHI_SettingsChanged *event) {
    (void)user;
    if (same(event->mod, own_id) && same(event->key, "report")) report();
}

TSUCHI_Result tsuchi_mod_start(const TSUCHI_Host *given, TSUCHI_Mod *mod) {
    uint64_t needed = 0;
    host = given;
    self = mod;
    TSUCHI_Result result = host->mod->id(mod, own_id, sizeof own_id, &needed);
    if (result != TSUCHI_OK) return result;
    report();
    return host->settings->on_changed(mod, on_changed, 0, &changes);
}
```

Every listener receives every mod's changes, so check both `mod` and `key`.
Setting a value to its current value doesn't emit an event. When a value changes,
the event arrives on the game thread at the start of the next world step.

## Typed values

On your mod's page, a `text` setting has an **Edit** button that opens the
system's keyboard with the current value. An `integer` setting keeps its arrows
and also gets **Edit**, and so does a `number` setting beside **Decrease** and
**Increase**. An integer whose `min` is `0` or more opens the number pad. Other
integers and all numbers open the full keyboard, since the number pad has no
minus sign or decimal point.

If the player types text longer than `max_length`, text that isn't a number, or a
value outside `min` and `max`, Tsuchi keeps the old value. Canceling the keyboard
keeps it too.

## Bindings

A `binding` setting holds one button that the player chooses. For example, let the
player pick a push-to-talk button on the controller:

```json title="mod.json"
"settings": {
  "talk_button": {
    "type": "binding",
    "default": "pad:zl",
    "accepts": "pad",
    "name": "Push to Talk Button"
  }
}
```

The value is text. A controller button is `pad:` and the button's name from
[`input`](/reference/input/)'s `Buttons`, such as `pad:zl` or `pad:left_stick`.
A keyboard key is `key:` and its USB HID usage, such as `key:23` for **T**. Set
`accepts` to `pad`, `key`, or `any` to choose what the player can pick. Leave it
out to allow both.

On your mod's page, the row shows the binding the way a player reads it, such as
**ZL** or **Keyboard: T**. When the player selects **Change Push to Talk Button**,
the row reads **Press a button...**, and the next button the player presses becomes
the binding. A keyboard binding reads **Press a key...** and takes the next key. The
**A** press that selected the row only counts if the player releases **A** and
presses it again. While the page waits, the game ignores the controller, so the
press doesn't also move the menu. To cancel, press **Esc** on a keyboard or wait five
seconds without pressing anything. **Esc** can't be bound.

Read the binding with `settings.text`, and check the button on each world step:

<Tabs syncKey="language">
<TabItem label="Lua">

```lua title="main.lua"
local function talk_held(player)
    local device, name = settings.text("talk_button"):match("^(%a+):(.+)$")
    if device == "pad" then
        local pad = input.pad(player)
        return pad ~= nil and pad.held[name] == true
    end
    return input.key(tonumber(name)) == true
end

time.on_step(function()
    if talk_held(0) then print("Talking") end
end)
```

</TabItem>

```javascript title="main.js"
function talk_held(player) {
    const [device, name] = settings.text("talk_button").split(":");
    try {
        if (device === "pad") return input.pad(player).held.includes(name);
        return input.key(Number(name));
    } catch (error) {
        return false;
    }
}

time.on("step", () => {
    if (talk_held(0)) print("Talking");
});
```

<TabItem label="C">

```c title="main.c"
#include "tsuchi/tsuchi.h"

static const TSUCHI_Host *host;
static TSUCHI_Mod *self;
static TSUCHI_Subscription steps;
static const char *const buttons[16] = {"a", "b", "x", "y", "left_stick", "right_stick", "l", "r",
                                        "zl", "zr", "plus", "minus", "left", "up", "right", "down"};

static bool same(const char *a, const char *b) {
    while (*a && *a == *b) { ++a; ++b; }
    return *a == *b;
}

static bool talk_held(uint32_t player) {
    char binding[24];
    uint64_t needed = 0;
    if (host->settings->text(self, "talk_button", binding, sizeof binding, &needed) != TSUCHI_OK) return false;
    if (binding[0] == 'k') { // key:<usage>
        uint32_t usage = 0;
        for (const char *digit = binding + 4; *digit; ++digit) usage = usage * 10 + (uint32_t)(*digit - '0');
        bool down = false;
        return host->input->key(self, usage, &down) == TSUCHI_OK && down;
    }
    TSUCHI_PadState pad;
    if (host->input->pad(self, player, &pad) != TSUCHI_OK) return false;
    for (uint32_t bit = 0; bit < 16; ++bit)
        if (same(binding + 4, buttons[bit])) return (pad.held & (1u << bit)) != 0;
    return false;
}

static void on_step(void *user, const TSUCHI_TimeStep *event) {
    (void)user;
    (void)event;
    if (talk_held(0)) host->mod->log(self, "Talking");
}

TSUCHI_Result tsuchi_mod_start(const TSUCHI_Host *given, TSUCHI_Mod *mod) {
    host = given;
    self = mod;
    return host->time->on_step(self, on_step, 0, &steps);
}
```

In C, bit `n` of `held` is the `n`th button in that list, the same order as the
`TSUCHI_BUTTONS_` values. When the player picks another button, your mod receives
the `changed` event like any other setting.

## Saving

Change your own values with calls such as `settings.set_toggle`, or call
`settings.reset` to restore the default. Tsuchi writes changes in the next frame,
or when the save next becomes writable. A refused write is retried after ten
seconds rather than on every frame.
If an update changes the allowed values and an old saved value no longer fits,
Tsuchi uses the new default.

Settings belong to the player and your mod, so they are shared across save slots.
Stopping or removing your mod doesn't erase the saved values.

## Public settings

If a setting has `"public": true`, another mod can read it as
`"olimar.clock:report"`. Other mods can't change it. Declare a dependency if the
other mod must be present, or handle `not_found` if reading its setting is optional.
Trying to read a private setting returns `denied`.

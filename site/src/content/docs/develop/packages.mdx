Use [`packages`](/reference/packages/) to install a mod package from an HTTPS URL. Tsuchi
downloads the file to the SD card, checks it, and installs it. Your mod chooses which file to
install. Tsuchi does the writing.

## Capability

Only a mod that declares the `packages` capability can use the service. Add it to `mod.json`:

```json title="mod.json"
{
  "id": "olimar.downloader",
  "name": "Downloader",
  "version": "1.0.0",
  "capabilities": ["packages"]
}
```

Without it, every `packages` call fails with `denied`.

## Packages

A package is a ZIP file of one of three kinds:

| Kind | Contents |
| --- | --- |
| Mods | One or more mod folders under `romfs/tsuchi/mods/`, as [Publish your mod](/develop/publish/) describes. |
| Assets | One cooked container: a `.pak`, `.utoc`, and `.ucas` of the same name. |
| Cheats | Cheat files named by the game's build ID, such as `060F827BD2B38703.txt`. |

One outer folder around the contents is accepted. Outside the mod folders, Tsuchi ignores only
`README.md`, `README.txt`, `LICENSE`, and `LICENSE.txt`. Any other file refuses the package.

The ZIP file can be up to 512 MiB, with up to 1 GiB expanded and 256 entries. Stored and DEFLATE
compression are supported. Encrypted, ZIP64, and split archives are refused.

Assets and cheats come without a manifest. Tsuchi installs them as one mod with the ID
`external.` followed by 24 hexadecimal digits made from the source and key. A new release of the
same source and key keeps that ID, whatever its files are named.

## Source and key

Every install names where the package comes from with two texts of your own: `source`, such as
`github`, and `key`, such as `olimar/tougher-bulborbs`. Tsuchi stores them and compares them byte
for byte. It never reads anything into them.

An install replaces an installed package when it has the same source and key and at least one of
the same mod IDs. Pass a mod ID as `replacing` when the player chose to update that mod. The install
then fails with `different` unless it replaces a package that holds that mod and the new package
holds it too.

## Install

Subscribe to [`packages.finished`](/reference/packages/#finished), then call `packages.install`
with the URL, the file's exact size, the source, the key, a title, and a release. Pass the file's
SHA-256 digest when you know it.

    local status = packages.status(event.install)

local install, why = packages.install(
    "https://example.com/releases/tougher-1.2.0.zip", 48213,
    "example", "olimar/tougher", "Tougher Bulborbs", "1.2.0")

static void finished(void *user, const TSUCHI_PackagesFinished *event) {

One install runs at a time across all mods. While it runs, `progress` reports the bytes downloaded,
then the bytes extracted. `packages.cancel` stops it. If your mod stops, the install stops too.

## Checks

Tsuchi publishes a package only after every check passes. A failed check leaves nothing installed,
and `failure` names the reason:

| Failure | Meaning |
| --- | --- |
| `network` | The download failed. |
| `http` | The server refused the download. |
| `size` | The file is not the size you gave. |
| `digest` | The file's SHA-256 digest is not the one you gave. |
| `archive` | The ZIP file is damaged or uses a format Tsuchi doesn't read. |
| `unsupported` | The ZIP file holds files that are none of the three kinds. |
| `storage` | The SD card refused the files. |
| `manifest` | A mod's manifest is invalid, is for another build, or conflicts with an installed mod. |
| `required` | A mod requires a mod that isn't installed. |
| `conflict` | A mod conflicts with an installed mod. |
| `different` | The package doesn't replace the mod named by `replacing`. |
| `receipt` | The record of the installation couldn't be saved. |

After a failure or a success, `packages.status` gives a sentence for the player in `message`.

## Installed packages

`packages.count` and `packages.at` list the installed packages, with the source, key, title,
release, file name, installation time, kind, and mod IDs of each. Compare them with your source to
find updates. The order changes when packages are installed or removed.

New mods load at the next start. A cooked container that the player has enabled also loads for new
loads at once. Reload the affected maps or objects to see it.

`packages.remove` removes a package. Its mods stop loading at the next start. Tsuchi deletes the
files once nothing loaded uses them, and deletes interrupted downloads when the game starts.
